# Qubit — BB84 Messenger

An orange-and-black messaging app with an inline BB84 startup flow, a conditional disturbance-detection planner, and IBM Quantum hardware demonstrations.

[Open the application](https://qubit-bb84-messenger.chalkypath1.chatgpt.site/)

## Experience

Choose a target chance of detecting a full intercept-resend attack, inspect the calculated transmission and public-sample budget, and follow five teaching qubits inside the chat window before starting a conversation. The walkthrough shows Alice's Z/X encoding, Eve's optional measurement and resend, Bob's results, basis sifting, and discarded public-sample comparisons. The interface uses self-hosted Poppins and very slightly rounded panels.

IBM jobs use the current Quantum Runtime REST API with server-side IAM authentication, owner-scoped job records, quota checks, and bounded execution. Hardware results identify the backend and job ID. Qiskit-generated simulation results are labeled separately and are never silently substituted for hardware.

## Security model

The displayed percentage is conditional on an ideal, full intercept-resend model. For m matching-basis public sample bits, the probability of observing at least one error is 1-(3/4)^m. A planned exchange rejects any sampled error and discards all revealed bits. A separate conservative sifting budget reserves at least 512 undisclosed bits with 99.9% basis-sifting confidence. This is not a finite-key QKD proof or a universal message-safety probability.

The five-qubit teaching sample is independent of conversation key material. IBM hardware runs on one processor; it is not a physical quantum link between remote users. Hardware noise can also cause mismatches. Chat keys are generated by the configured trusted-backend BB84 simulator and derived with HKDF-SHA-256; messages use AES-256-GCM with fresh nonces and authenticated context. The backend can decrypt authorized reads, so this is not end-to-end encryption.

## Hosting

This repository contains the source and a GitHub Pages launch page. GitHub Pages serves static files and links visitors to the full application, whose backend and database run on the existing hosting service. GitHub Pages does not receive IBM credentials or conversation keys.

Server secrets are configured only in the backend runtime. No API keys, local secret files, local database state, or private local-running guide belong in this repository.

## Code organization

- app/ — chat interface, inline walkthrough, and server routes.
- lib/ — probability planning, encryption, Qiskit bridge, and IBM hardware integration.
- db/ and drizzle/ — database schema and append-only migrations.
- qiskit_service/ — optional Python Qiskit simulator.
- tests/ — protocol, authorization, planning, and integration verification.
- docs/ — static GitHub Pages launch page.

The source includes tests for confidence calculations, planned sampling, message tampering, room access, Qiskit interoperability, and IBM job boundaries. Real hardware availability and execution timing depend on IBM's queue and instance allocation.
